# oscript-md

Markdown-парсер и рендерер на чистом OneScript. Без зависимостей от Markdig
или другой нативной библиотеки — реализация работает в любой среде, где есть
OneScript.

Поддерживается ядро **CommonMark 0.31.2** и набор расширений
**GitHub-Flavored Markdown** (tables, tasklists, strikethrough, autolinks).
Недоверенный Markdown рендерится сразу в безопасный HTML — санитизация по
allowlist входит в библиотеку, отдельного санитайзера не нужно.

## Установка

Из хаба opm:

```bash
opm install oscript-md
```

Из исходников (например, склонированный репозиторий):

```bash
opm install --local
opm build .
```

После установки библиотека доступна в любом скрипте через стандартное:

```bsl
#Использовать "oscript-md"
```

## Быстрый старт

```bsl
#Использовать "oscript-md"

HTML = Markdown.ВHTML("# Привет, мир!");
// → "<h1>Привет, мир!</h1>" + Символы.ПС
```

Функции фасада `Markdown.*`:

| Функция | Что возвращает | Когда полезна |
|---|---|---|
| `Markdown.ВHTML(текст[, настройки])` | HTML-строку | Рендеринг в веб/email/preview |
| `Markdown.ВБезопасныйHTML(текст[, настройки[, allowlist]])` | санитизированный HTML | **Недоверенный** Markdown: README, комментарии, ввод пользователя |
| `Markdown.Разобрать(текст[, настройки])` | `MarkdownДокумент` (AST) | Программная обработка содержимого |
| `Markdown.ВJSON(текст[, настройки])` | JSON-сериализация AST | Snapshot-тесты, интеграции, отладка |
| `Markdown.ВТекст(текст[, настройки])` | plain text без разметки | Telegram, email, логи, changelog |

Отдельно доступна санитизация произвольного HTML — см. раздел
[«Санитизация недоверенного HTML»](#санитизация-недоверенного-html).

## Примеры использования

### HTML-рендеринг

```bsl
#Использовать "oscript-md"

Исходник =
    "# Заголовок"   + Символы.ПС +
    ""              + Символы.ПС +
    "Параграф с **жирным** и *курсивом*." + Символы.ПС +
    ""              + Символы.ПС +
    "- пункт списка" + Символы.ПС +
    "- ещё пункт";

Сообщить(Markdown.ВHTML(Исходник));
// <h1>Заголовок</h1>
// <p>Параграф с <strong>жирным</strong> и <em>курсивом</em>.</p>
// <ul>
// <li>пункт списка</li>
// <li>ещё пункт</li>
// </ul>
```

### Работа с AST

```bsl
Документ = Markdown.Разобрать("# Привет" + Символы.ПС + Символы.ПС + "Параграф");

Сообщить(Документ.Дети.Количество());        // 2
Сообщить(Документ.Дети[0].ТипУзла());        // heading
Сообщить(Документ.Дети[0].Уровень);          // 1
Сообщить(Документ.Дети[1].ТипУзла());        // paragraph
```

AST-узлы доступны напрямую — можно собирать документы программно:

```bsl
Документ = Новый MarkdownДокумент();
Заголовок = Новый MarkdownЗаголовок(2);
Заголовок.Добавить(Новый MarkdownТекст("Сгенерировано"));
Документ.Добавить(Заголовок);

Рендерер = Новый MarkdownHTMLРендерер();
HTML = Рендерер.Отрендерить(Документ);       // <h2>Сгенерировано</h2>
```

### JSON-сериализация AST

```bsl
JSON = Markdown.ВJSON("# Hi");
// {"type":"document","children":[
//   {"type":"heading","level":1,"children":[
//     {"type":"text","value":"Hi"}
//   ]}
// ]}
```

### Plain text

```bsl
Текст = Markdown.ВТекст("# Заголовок" + Символы.ПС + Символы.ПС + "Параграф *с курсивом*");
// "Заголовок\n\nПараграф с курсивом"
```

### Пресеты настроек

```bsl
// Чистый CommonMark без расширений.
Настройки = Markdown.НастройкиCommonMark();

// CommonMark + tables + tasklists + strikethrough + autolinks.
Настройки = Markdown.НастройкиGitHubLike();

// CommonMark + по умолчанию ничего, но безопасный режим включён.
Настройки = Markdown.НастройкиПоУмолчанию();

HTML = Markdown.ВHTML(Текст, Настройки);
```

Доступные пресеты: `commonmark` (он же `minimal`), `default`, `github-like`,
`documentation`, `zero`.

### Включение/отключение отдельных расширений

```bsl
Настройки = Новый MarkdownНастройки("commonmark");
Настройки.Расширения.Включить("tables");
Настройки.Расширения.Включить("strikethrough");

HTML = Markdown.ВHTML(Текст, Настройки);
```

### GFM-таблицы

```bsl
МД =
    "| Колонка 1 | Колонка 2 |" + Символы.ПС +
    "|-----------|:---------:|" + Символы.ПС +
    "| A         | B         |" + Символы.ПС +
    "| C         | D         |";

HTML = Markdown.ВHTML(МД, Markdown.НастройкиGitHubLike());
// <table>
//   <thead><tr><th>Колонка 1</th><th align="center">Колонка 2</th></tr></thead>
//   <tbody>
//     <tr><td>A</td><td align="center">B</td></tr>
//     <tr><td>C</td><td align="center">D</td></tr>
//   </tbody>
// </table>
```

### Списки задач (tasklists)

```bsl
МД =
    "- [x] выполнено" + Символы.ПС +
    "- [ ] в работе";

HTML = Markdown.ВHTML(МД, Markdown.НастройкиGitHubLike());
// <ul>
//   <li><input type="checkbox" checked disabled /> выполнено</li>
//   <li><input type="checkbox" disabled /> в работе</li>
// </ul>
```

### Безопасный режим

По умолчанию `БезопасныйРежим = Истина`: raw HTML экранируется, опасные
конструкции не пройдут в выход.

```bsl
HTML = Markdown.ВHTML("<script>alert(1)</script>");
// "&lt;script&gt;alert(1)&lt;/script&gt;"
```

Чтобы разрешить raw HTML (например, для доверенного содержимого):

```bsl
Настройки = Markdown.НастройкиПоУмолчанию();
Настройки.БезопасныйРежим = Ложь;
Настройки.РазрешитьRawHTML = Истина;
```

## Санитизация недоверенного HTML

Безопасный режим экранирует **сырой HTML из исходника**, но не проверяет то, что
собирает сам рендерер: ссылку `[зло](javascript:alert(1))` он честно превратит в
`<a href="javascript:alert(1)">`. Для содержимого, которое написал не вы —
README чужого пакета, комментарий, форма — нужен второй рубеж: санитизация
готового HTML по принципу allowlist.

```bsl
#Использовать "oscript-md"

// Рендер + очистка одним вызовом — обычный путь для недоверенного текста.
HTML = Markdown.ВБезопасныйHTML(ТекстREADME);

// Очистка произвольного HTML (не обязательно markdown-происхождения).
HTML = Markdown.ОчиститьHTML(НедоверенныйHTML);
```

| Функция | Назначение |
|---|---|
| `Markdown.ВБезопасныйHTML(текст[, настройки[, allowlist]])` | Разобрать Markdown, отрендерить и санитизировать |
| `Markdown.ОчиститьHTML(HTML[, allowlist])` | Санитизировать готовый HTML |
| `Markdown.НастройкиСанитизацииПоУмолчанию()` | Профиль allowlist для markdown-вывода (новый объект на каждый вызов) |
| `Markdown.ПустыеНастройкиСанитизации()` | Пустой allowlist: снимается вся разметка |

### Профиль по умолчанию

Разрешено ровно то, что печатает `MarkdownHTMLРендерер`:

| Теги | Разрешённые атрибуты |
|---|---|
| `p` `br` `hr` `h1`…`h6` `ul` `ol` `li` `strong` `em` `del` `blockquote` `table` `thead` `tbody` `tr` `details` `summary` | — |
| `code` `pre` | `class` — только `language-*` |
| `a` | `href` (схема из allowlist), `title` |
| `img` | `src` (схема из allowlist), `alt`, `title` |
| `th` `td` | `align` — только `left`/`center`/`right` |

Схемы URL: `http`, `https`, `mailto`; относительные адреса и якоря проходят.
Внешним ссылкам добавляется `rel="nofollow noopener"`.

### Свой allowlist

```bsl
Настройки = Markdown.НастройкиСанитизацииПоУмолчанию()
    .ЗапретитьТег("img")                       // тег снимается, содержимое остаётся
    .УдалятьТегССодержимым("blockquote")       // тег удаляется вместе с содержимым
    .РазрешитьПротокол("ftp")
    .УстановитьRelВнешнихСсылок("nofollow noopener noreferrer");

HTML = Markdown.ВБезопасныйHTML(Текст, Неопределено, Настройки);
```

Полностью свой профиль строится от пустого:

```bsl
Настройки = Markdown.ПустыеНастройкиСанитизации()
    .РазрешитьТег("p")
    .РазрешитьТег("a", "href, title");
```

### Что санитайзер гарантирует

- в выходе встречаются только разрешённые теги и разрешённые атрибуты — вывод
  собирается заново из потока токенов, а не «латается» регулярками, поэтому
  mutation-XSS через кривую вложенность не проходит;
- текст и значения атрибутов всегда экранированы;
- `href`/`src` проверяются по схеме **после** нормализации: HTML-сущности
  раскодируются (`javascript&colon;`, `&#106;avascript:`), управляющие и
  невидимые символы (таб, перевод строки, zero-width, BOM, RTLO) удаляются;
- опасные контейнеры (`script`, `style`, `iframe`, `object`, `embed`, `form`,
  `svg`, `math`, `template`, …) удаляются **вместе с содержимым**;
- незакрытые разрешённые теги закрываются, лишние закрытия отбрасываются,
  комментарии, CDATA, доктайпы и инструкции обработки удаляются;
- при дублировании атрибутов действует первый — так же, как в браузере.

### Чего санитайзер не делает

- **не проверяет домены**: гомоглиф в имени хоста (`аpple.com` с кириллической
  «а») — валидный URL, защита от фишинга лежит вне санитайзера;
- **не разбирает CSS**: атрибут `style` не разрешён вовсе, а не фильтруется;
- **не сохраняет чекбоксы списков задач**: `input` не входит в профиль по
  умолчанию, у пункта остаётся только текст. Если чекбоксы нужны, разрешите тег
  явно — значение `type` при этом ограничено `checkbox`:

  ```bsl
  Настройки = Markdown.НастройкиСанитизацииПоУмолчанию()
      .РазрешитьТег("input", "type, checked, disabled");
  ```

- **не является заменой Content-Security-Policy**: это второй рубеж, а не
  единственный.

### Свои расширения

Расширения регистрируют свои компоненты в `MarkdownРеестрКомпонентов` через
метод `Зарегистрировать(Реестр)`. Полная схема — в исходниках расширений
[src/extensions/Классы/](src/extensions/Классы/) (tables / tasklists /
strikethrough / autolinks).

## Известные ограничения CommonMark

Шесть примеров официальной CommonMark 0.31.2 conformance suite сейчас
помечены `&Выключен` и не падают CI. Все случаи касаются тонкостей
container-модели (CM §4.7) и относятся к одной из трёх групп.

### Табуляция в контейнерных блоках (CM §2.2)

Расширение табов на границе контейнера (список, цитата) рассчитано не до
конца — нужна полноценная обработка префикса строки контейнера на
смешанных tab/space отступах.

| # | Что не работает |
|---|---|
| 5 | Tab внутри элемента списка — расширение таба на границе контейнера |
| 6 | Tab внутри цитаты — расширение через границу маркера `>` |
| 7 | Tab внутри элемента списка — расчёт отступа при двойном табе |

### Setext-заголовок в lazy continuation

| # | Что не работает |
|---|---|
| 93 | Setext-подчёркивание в строке ленивого продолжения цитаты. CM запрещает создавать setext-заголовок из lazy continuation line, у нас он создаётся |

### Закрытие/границы блоков внутри цитат

| # | Что не работает |
|---|---|
| 236 | Цитата + indented code block: CM считает внешнее indented-содержимое отдельным блоком, наш парсер цитат захватывает его через lazy continuation |
| 237 | Fenced code внутри цитаты без закрывающего ограждения: закрывающий fence тоже должен нести префикс `>`; без него ограждение остаётся открытым до конца цитаты |

Скрипт-генератор тестов хранит этот список внутри
[tools/sync-commonmark.py](tools/sync-commonmark.py) (константа `SKIP_LIST`).
При исправлении соответствующего бага в парсере нужно убрать номер из
константы и перегенерировать сьюты.

## Тестирование

`tasks/*.os` дёргают `oneunit` как CLI, поэтому он должен быть в `PATH` —
ставим его глобально. `asserts` и `1commands` подтянутся как локальные
dev-зависимости из `packagedef`.

```bash
opm install oneunit                     # test-runner глобально (нужен в PATH)
opm install --local --dev               # asserts, 1commands → ./oscript_modules
oscript tasks/test.os                   # все тесты + JUnit-отчёты в build/reports/
oscript tasks/test_unit.os              # только юнит-тесты
oscript tasks/test_commonmark.os        # только CommonMark conformance
```

CommonMark-сьюты автогенерируются из официальной спецификации. Список
xfail-примеров хранится в самом скрипте (`SKIP_LIST` в начале файла):

```bash
python tools/sync-commonmark.py 0.31.2
```

Подробнее об устройстве — в [paln.md](paln.md).
